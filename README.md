# Mimiao Threads Studio

Отдельная админка для `@mimiao.crm`: исследование украинских обсуждений, генерация через DeepSeek, публикации с фотографиями, редактор, статистика и работа с ответами. Интерфейс — русский, тексты публикаций — украинские. Проект не зависит от CRM и не использует её базу, секреты или сервер.

## Быстрый запуск на этом компьютере

Требуются Node.js >=22.12 и Docker Desktop.

```powershell
cd F:\Programming\projects\mimiao-threads-studio
npm ci
npm run setup
docker compose -f compose.dev.yml up -d db
npm run db:migrate
npm run dev
```

Откройте **http://127.0.0.1:5179**. Пароль первого входа записан в `OWNER-LOGIN.local.txt`; сохраните его в менеджере паролей и удалите этот файл. `setup` не перезаписывает существующий `.env`. API работает на 4319, PostgreSQL — только на localhost:55439. `npm run dev` запускает API, Vite и worker вместе. Если процесс остановлен или компьютер спит, расписание не выполняется; для круглосуточной работы нужен VPS.

Реальные ключи задаются в приватном `.env` сервера. Проверки интеграций используют отдельную тестовую базу и имитацию ответов провайдеров. Автопубликация требует одновременно `LIVE_PUBLISHING=true`, подключённый Threads и снятую паузу в интерфейсе.

## Что работает

Интерфейс оформлен в тёмном графите с янтарными акцентами: линия расписания, ближайшая публикация, готовность завтрашнего плана и предпросмотр текста/фотографий в редакторе. На телефоне предпросмотр переключается отдельной кнопкой. Внизу меню можно выбрать полные или спокойные эффекты; выбор хранится в этом браузере. Системное уменьшение движения имеет приоритет. График доступен с клавиатуры, редактор закрывается по Escape и возвращает фокус.

- Рабочий стол и календарь: план на завтра, черновики, статусы, ошибки, ручное создание и отмена.
- Редактор: два варианта текста, рубрика, время, причины правок, история версий, фотографии и изменение их порядка. JPEG, PNG, WebP до 15 МБ; нормализация в JPEG, удаление EXIF. 1 фото — изображение, 2–20 — карусель.
- Ежедневное исследование: ключевые слова, заданные профили, украинские образовательные и культурные обсуждения. Ссылки, даты, уверенность, срок актуальности. Без Advanced Access Meta охват явно ограничен веб-поиском DeepSeek и ссылками владельца.
- Банк идей: наблюдения, ссылки, решения «в работу / отклонить» и причины. Правки и последние недельные выводы передаются в следующие генерации.
- Статистика: API-замеры 1/24/72 часа и 7 дней, отдельный импорт старой истории, общий рост подписчиков, сравнение рубрик, ручные показатели поста и CSV.
- Обсуждения: комментарии к своим постам, классификация содержательности, черновики ответов. При доступном публичном поиске — предложения участия в свежих чужих обсуждениях. **Отправка ответа всегда отдельной кнопкой владельца.**
- Голос, подтверждённые факты, запрещённые формулировки, модель, ключевые слова, профили и частота настраиваются в интерфейсе.
- Генерация постов, альтернатив, замен устаревших тем и ответов получает полный навык общения с клиентами: `SKILL.md`, исходный творческий бриф и плейбук Mimiao без сокращений, плюс адаптацию к Threads. Все исходники видны в «Голос и знания», личные настройки дополняют их. Цены и старые офферы из плейбука не считаются актуальными фактами. Источник и границы: [docs/client-voice.md](docs/client-voice.md).
- Подключения: OAuth Threads, проверка доступов, обновление токена, журнал, признаки активности worker и использование API. Уведомления только внутри админки. Денежных лимитов нет.

## Ежедневный цикл · Europe/Kyiv

| Когда | Задача |
| --- | --- |
| 06:00 | Сверка доступной истории аккаунта |
| 07:00 | Проверка и обновление истекающего токена |
| 17:30 | Проверка эксперимента частоты |
| 18:00 | Поиск и анализ источников |
| 19:00 | Полный план на завтра |
| Каждую минуту | Публикация подходящего поста из очереди |
| Каждые 5 минут | Сверка неизвестных результатов отправки |
| Каждые 10 минут | Проверка срока актуальности тем перед публикацией |
| Каждые 15 минут | Статистика и комментарии |
| Понедельник 10:00 | Недельный разбор |

По умолчанию 10 постов с 09:00 до 22:30; в настройках доступно 5–10 постов в день. Автоматический план выбирает время в окне 08:00–23:00. Для сегодняшнего плана время выбирается из оставшейся части дня; при необходимости интервалы сокращаются, чтобы весь план поместился до конца дня. Вручную можно назначить любое будущее время, включая ночь. Часовой пояс Europe/Kyiv учитывает переходы летнего времени. Время адаптируется после минимум 5 сопоставимых замеров для часа. Это история **вашего аккаунта**, а не измерение активности всех пользователей Threads.

После 28 дней сопоставимых данных можно автоматически начать 28-дневный эксперимент: текущая частота против +1 поста. Дни недели сбалансированы. Максимум — 10. Увеличение требует достаточного числа содержательных ответов, отсутствия ухудшения медианы охвата и общего прироста подписчиков. Это наблюдательный эксперимент, не доказательство причинности. Адаптацию можно выключить.

Обычная автоматическая подготовка не перезаписывает готовый план. Кнопки подготовки на сегодня и завтра явно перегенерируют все неопубликованные посты выбранного дня: прежние версии архивируются с сохранением истории правок, опубликованные посты остаются. Фотографии сохраняются в архивных оригиналах и автоматически не прикрепляются к новым текстам. Если модель или проверка генерации завершилась ошибкой, прежняя очередь сохраняется; частичный план не сохраняется. После 19:00 worker восстанавливает пропущенную генерацию на завтра; неуспешную повторяет до трёх автоматических попыток с интервалом 30 минут. Кнопки позволяют повторить вручную после исправления причины.

## Подключение сервисов

Если доступа к Meta for Developers пока нет, доступен отдельный [режим публикации через браузер](docs/browser-publishing.md). Для Camoufox Profile Manager используется `compose.camoufox.yml`, для обычного Chromium — `compose.browser.yml` (выберите один). Владелец входит в Threads в защищённом окне, затем worker публикует запланированные тексты и фото. При потере входа или неизвестном результате очередь останавливается. API-статистика и импорт этим режимом не заменяются.

Добавьте в `.env`, затем перезапустите API и worker:

```dotenv
DEEPSEEK_API_KEY=your-secret
THREADS_APP_ID=your-app-id
THREADS_APP_SECRET=your-secret
PUBLIC_URL=https://studio.your-domain.example
STUDIO_DOMAIN=studio.your-domain.example
LIVE_PUBLISHING=false
THREADS_PUBLIC_DISCOVERY_APPROVED=false
```

DeepSeek по умолчанию: `deepseek-flash`, JSON-ответы и Search API. Ключ используется только на сервере. Проверяются структура, длина, запрещённые выражения, повторы, ссылки и самооценка фактических утверждений. Автоматическая проверка модели **не гарантирует истинность**; проверенные знания и ваши редакторские правки остаются важны.

В приложении Meta добавьте Threads use case и redirect URI:

```text
https://studio.your-domain.example/api/integrations/threads/callback
```

Доступы: `threads_basic`, `threads_content_publish`, `threads_manage_insights`, `threads_read_replies`, `threads_keyword_search`, `threads_profile_discovery`. В интерфейсе: «Подключения → Подключить Threads». Подключение принимает только `mimiao.crm`. Если имя аккаунта изменится, обновите проверку в `server/routes/integrations.ts` и подписи интерфейса.

Для разработки владелец должен быть допущен к тестированию приложения Meta. Для мониторинга чужих аккаунтов нужен Advanced Access / App Review. Только после подтверждённого одобрения выставьте `THREADS_PUBLIC_DISCOVERY_APPROVED=true`, перезапустите сервисы и нажмите «Проверить доступ». Обычный успешный запрос стандартного доступа не считается доказательством полного публичного поиска. Если отдельный scope не выдан, соответствующая возможность будет недоступна; публикация сама по себе не доказывает доступность аналитики или поиска.

Предусмотрены страницы `/privacy` и `/deletion`. Перед App Review проверьте их соответствие фактической эксплуатации и требованиям вашего приложения Meta; одобрение не гарантировано.

После подключения импортируется доступная история последних 90 дней (пагинация ограничена 2000 записями на тип). На старых постах нельзя восстановить настоящие показатели на 24/72 часу. Такие замеры помечены `import`, а ответы владельца не смешиваются с исходными постами.

## Честная аналитика

Threads API даёт просмотры, лайки, ответы, репосты, цитаты и shares для поста, а также общий `followers_count`. Подписки и переходы в профиль **от конкретного поста** в этой реализации вводятся вручную из интерфейса Threads; система не распределяет общий прирост по постам.

`—` означает нет данных. Ноль сохраняется только при полученном нуле. Сравнение рубрик и подбор времени используют исходные посты с замером 24h, фактически снятым в возрасте 24–28 часов. Поздние замеры хранят свой реальный возраст и не попадают в эту выборку. Просмотры профиля аккаунта показываются за скользящее окно 24 часа на момент сбора. Это не обязательно совпадает с одноимённым показателем приложения Threads.

Поэтому причину прежнего падения охватов нельзя подтвердить одним подключением: нужны доступная история, реальные старые показатели и новые сопоставимые наблюдения. Автопостинг через DeepSeek сам по себе не гарантирует рост.

## Развёртывание на отдельном VPS

1. Подготовьте Ubuntu 24.04 по [инструкции настройки VPS](deploy/README.md): Docker Engine + Compose, SSH, firewall и системные обновления. Настройте DNS поддомена на новый сервер. Не используйте контейнеры/базу CRM.
2. Скопируйте проект без `node_modules`, `dist`, тестовых файлов и локальных данных. Установите зависимости и выполните `npm run setup` на доверенной машине либо перенесите сгенерированный `.env` по защищённому каналу. Секреты не коммитить.
3. В production `.env` сохраните сгенерированные `POSTGRES_PASSWORD`, `ENCRYPTION_KEY`, `SESSION_SECRET`, `ADMIN_PASSWORD_HASH`; задайте публичный URL, домен и ключи API. Файл должен читаться только владельцем (`chmod 600 .env` на Linux). Пароль PostgreSQL из setup состоит из hex-символов и безопасен для URI.
4. Запустите:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 api worker
```

Caddy выпускает HTTPS-сертификат. PostgreSQL и API не открывают порты наружу. Контейнеры API/worker запускаются непривилегированным пользователем; база, фото и сертификаты находятся в отдельных volumes. Production и dev Compose имеют одно имя проекта: **не запускайте их одновременно на одном Docker-хосте**. На новом VPS используется только `compose.yml`.

5. Войдите, подключите Threads, проверьте доступы и факты бренда, загрузите фото и проверьте его отображение. Сначала оставьте публикацию на паузе.
6. Для реальной работы задайте `LIVE_PUBLISHING=true`, выполните `docker compose up -d --force-recreate api worker` и снимите паузу в админке. Защита на уровне переменной окружения не заменяет общую паузу.

Meta скачивает фото по подписанной HTTPS-ссылке с ограниченным сроком жизни. `localhost` для этого не подходит. Приватные медиа без сессии или подписи недоступны.

## Ошибки и восстановление работы

- `blocked`: исправьте причину в редакторе и снова поставьте в очередь. Фотография не удаляется автоматически ради успешного текстового поста.
- `unknown`: запрос мог быть принят Meta. Повторная отправка заблокирована. Автоматическая сверка проверяет статус контейнера и ищет единственное совпадение текста в аккаунте. Можно вручную указать числовой API ID опубликованного поста; система проверит автора и текст. Если доказательства нет, запись остаётся неизвестной — проверьте аккаунт перед ручным созданием замены.
- `missed`: публикация просрочена больше чем на 30 минут. Перенесите её вручную. После простоя система не отправляет пачку накопившихся постов.
- Устаревшая тема заменяется вечным вопросом только после успешной генерации и проверки. Если есть фотографии, пост блокируется до проверки их соответствия новому тексту.
- Неизвестный результат ответа на комментарий также не отправляется повторно. Проверьте его в Threads. Ручное разрешение неизвестных ответов пока выполняется оператором по журналу.
- При истечении/отзыве токена переподключите Threads. Смотрите статус и журнал в «Подключениях».
- Для смены пароля создайте новый scrypt-хеш через `hashPassword` из `server/security.ts`, обновите `ADMIN_PASSWORD_HASH`, очистите таблицу `sessions` и перезапустите API. Не передавайте пароль аргументом общей shell-команды.

## Хранение данных

Резервное копирование не используется по решению владельца. База и фотографии хранятся в постоянных Docker volumes `database` и `media`.

Полное удаление данных владельцем: остановить отдельный проект Studio, отозвать приложение в Threads и удалить только принадлежащие Studio volumes и секреты. Предварительно проверьте имена ресурсов. Отключение аккаунта в интерфейсе удаляет токен из активной базы.

## Проверки

```powershell
npm test
npm run test:integration
npm run build
npm audit
docker build -t mimiao-threads-studio:local .
python tests/browser_smoke.py
python tests/design_browser.py
```

Интеграционные тесты создают/очищают только `studio_test` в локальном PostgreSQL. Нужна роль с CREATE DATABASE; **не запускать против production**. Браузерный smoke требует `pip install playwright`, `python -m playwright install chromium`, запущенный `npm run dev` и файл первого пароля. Он не сохраняет и не отправляет посты. Артефакты проверок лежат в игнорируемом `test-results/`.

Архитектурные правила и границы: [docs/architecture.md](docs/architecture.md).

Проверка дизайна перехватывает API только внутри тестового браузера: восемь заполненных разделов на ширинах 390, 768, 1440 и 1920, предпросмотр, порядок фото, фокус, мобильное меню, спокойные эффекты, загрузка и ошибки. Примеры не попадают в базу и не публикуются. Скриншоты сохраняются в `test-results/design-*.png`. Визуальные правила: [docs/interface.md](docs/interface.md).
